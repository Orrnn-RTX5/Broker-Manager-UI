BACKEND BLOCKERS / CONTRACT MISMATCHES

1. GET /reports/v1/summary is integrated, but the live TEST broker returned HTTP 404 during focused browser verification. The dashboard falls back to other live account metrics, but the report-summary KPI source cannot work until the backend route is deployed/fixed.

2. POST /api/v1/manager/positions/{ticket}/force-close returned HTTP 409 with code GO_EXECUTION_RETIRED on the live broker. The response says to use a supported Rust command. The frontend therefore uses POST /api/v1/manager/orders/{ticket}/close for normal selected-position close actions.

3. /IBPayoutRequest, /IBPayoutApprove, and /IBPayoutReject are not in the supplied manager catalog and returned 404. The inactive frontend code that assumed these routes was removed. Add a documented payout API before rebuilding this UI.

4. The supplied catalog contains endpoint names and descriptions but no request/response schemas. New high-risk write screens should not be guessed from names alone. Publish OpenAPI request bodies, enums, error models, and idempotency behavior before adding the remaining finance/payment/product mutations.

5. Existing UI routes missing from the supplied catalog:
- Groups: /GroupList (live read returned 200), /GroupCreate, /GroupUpdate, /GroupDelete, /GroupStats, /GroupMoveAccounts.
- Extended symbols: /SymbolAdd, /SymbolUpdate, /SymbolEnable, /SymbolDisable, /SessionOverrideList, /SessionOverrideSet, /SessionOverrideDelete, /SymbolSessionGet, /SymbolSessionSet, /DynamicLeverageList, /DynamicLeverageCreate, /DynamicLeverageDelete, /CommissionScheduleList, /CommissionScheduleCreate, /CommissionScheduleDelete, /SwapFreeGroupList, /SwapFreeGroupSet, /SwapFreeGroupDelete, /MarketDepthConfigGet, /MarketDepthConfigSet, /SymbolVisibilityList, /SymbolVisibilityGet, /SymbolVisibilitySet.
- Several of those extended read endpoints returned 200 in the UI, so they were not removed. The backend catalog should be updated. GroupDelete, GroupMoveAccounts, SymbolAdd/Update/Enable/Disable, and some delete endpoints are currently undocumented GET mutations; the backend should provide documented POST/PATCH/DELETE successors.
